# Web Viewer — Static Read-Only Site

> A browsable, read-only view of the sync repo. No backend. No auth. Generated by Astro, deployed to GitHub Pages from the sync repo.

## Problem

The desktop app requires an install. On a machine where Curaye isn't installed — a second device, a borrowed laptop — there is no way to browse project specs without cloning the sync repo and reading raw markdown files.

## Goal

An Astro static site that reads `.curaye/` content from the sync repo at build time and generates a browsable, read-only HTML view. Deployed automatically to GitHub Pages on every push to the sync repo.

## Non-goals

- Write operations of any kind — this is strictly read-only.
- Authentication — the site is as private as the GitHub Pages deployment. Private repos require GitHub Pro for private Pages; that is the user's decision.
- Real-time updates — the site rebuilds on push, not on demand.
- The full desktop app feature set — no AI, no kanban, no backlog view.

## Site structure

```
/                         ← project list (all registered projects)
/[project-id]/            ← project overview (prd.md + stats)
/[project-id]/planned/    ← planned specs list
/[project-id]/planned/[id]  ← individual spec
/[project-id]/current/    ← current docs list
/[project-id]/current/[id]
/[project-id]/shipped/    ← shipped docs list
/[project-id]/shipped/[id]
/[project-id]/decisions/  ← decisions list
/[project-id]/decisions/[id]
/shared/                  ← shared layer overview
/shared/[section]/[id]    ← individual shared document
```

## Build process

Astro reads from the sync repo's directory structure at build time using `@curaye/core`'s `scanProject`. Each project folder in the sync repo maps to a project in the site. The `projects.yaml` in the sync repo provides names and metadata (no local paths — the web viewer doesn't need them).

GitHub Actions workflow in the sync repo:

```yaml
on: [push]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - run: pnpm install
      - run: pnpm build          # builds @curaye/web
      - uses: peaceiris/actions-gh-pages@v4
        with:
          publish_dir: apps/web/dist
```

## Design

Minimal. Markdown content rendered with syntax highlighting. Status badges on planned specs. No heavy framework UI — just readable, well-typeset documents.

The `@curaye/ui` package provides shared components for status badges and document cards, reused from the desktop app.

## Acceptance criteria

1. Pushing to the sync repo triggers a GitHub Actions build that deploys the updated site.
2. The project list page shows all projects from `projects.yaml` with their names and a count of planned/shipped specs.
3. An individual planned spec renders the frontmatter fields as a structured header and the markdown body below.
4. Status badges (draft, ready, building, done, shelved) render with correct visual treatment.
5. Draft documents (`_` prefix) are excluded from all rendered pages.
6. The site builds with zero errors on the Curaye project's own `.curaye/` content.
7. All pages are valid HTML with semantic structure (headings, nav, main).
8. The site works without JavaScript enabled (static HTML only).
