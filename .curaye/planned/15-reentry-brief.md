# Re-entry Brief — Dormant Project Revival

> Return to something untouched for months and receive a structured brief: current state, where you left off, what's next, and anything that needs revisiting. The warm handoff to yourself.

## Problem

Returning to a dormant project is expensive. The mental model is gone. Reconstructing it means reading old code, git history, and notes scattered across tools. This is the tax that makes developers avoid picking up side projects they genuinely want to finish.

## Goal

A re-entry brief: an AI-generated, structured summary of a project's state produced from its `.curaye/` contents. Available via CLI and desktop app. Reduces time-to-context from hours to minutes.

## Non-goals

- Real-time project analysis (reading source code beyond `.curaye/`) — the brief is derived from `.curaye/` only.
- Replacing the actual work of reviewing code — the brief orients, not substitutes.
- Persistent chat about the project — a single-shot generation, not a conversation.

## Brief structure

The output follows a fixed structure regardless of the project:

```
─────────────────────────────────────────
CURAYE  Re-entry Brief: Ilmgah
Last activity: 4 months ago (2026-03-12)
─────────────────────────────────────────

CURRENT STATE
[3–5 sentence summary of what the project does today, derived from current/]

Reader, library, highlights, TTS, and search are shipped.
Glass UI has 12 components in current/. The reader supports
paginated and scrolled flow with foliate-js.

WHAT WAS PLANNED
[List of planned specs with status, sorted by status: building first, then ready, then draft]

  building  llm-provider (m)   — Unblocks 3 other specs
  ready     auto-scroll (s)    — Independent, buildable now
  draft     ask-the-book (l)   — Requires llm-provider

WHERE YOU LEFT OFF
[The spec most recently updated, with a one-sentence summary]

Last touched: llm-provider, updated 2026-03-10.
"Abstract the LLM provider to support Ollama, Anthropic, and OpenAI."

DECISIONS TO REVISIT
[Any decisions that reference libraries with known updates, or that reference status: superseded]

  ⚠  tauri-plugin-sql referenced in decisions/why-sqlite.md — v2.2 released
  ⚠  foliate-js v3 released — you noted you were watching this

SUGGESTED FIRST STEP
[Single recommendation: what to build next and why]

Build llm-provider — it unblocks ask-the-book and two other planned
specs. Estimated effort: m.

VISION CHECK
[One sentence confirming whether planned specs align with prd.md]

All planned specs align with the calm reading experience north star.
─────────────────────────────────────────
```

## Generation

The brief is generated by the AI provider with a structured prompt that includes:

- `prd.md` — the north star
- `stack.md` — tech context for the "decisions to revisit" section
- All `current/` documents — for the current state summary
- All `planned/` documents with their status and `updated` date
- All `decisions/` documents — for the revisit candidates

The "decisions to revisit" section is a mix of AI inference (libraries that may have updated) and deterministic checks (decisions with `status: superseded`).

Without AI configured, the brief is generated deterministically from the structured data — the current state section is replaced by a list of `current/` document titles; the suggested first step is the `building` spec or the highest-impact `ready` spec.

## CLI

```
curaye brief [--project <id>]
```

Streams the brief to stdout. `--no-ai` forces deterministic generation.

```
curaye brief --save [--project <id>]
```

Generates and saves the brief to `.curaye/briefs/YYYY-MM-DD.md`. Briefs are not tracked by the protocol scanner — they are a log, not a spec.

## Desktop integration

The re-entry brief surfaces in two ways:

1. **On project selection**: if a project has not been opened in Curaye for > 30 days, a "Generate re-entry brief" prompt appears at the top of the tree panel.
2. **Manual trigger**: a "Brief" button in the project panel header, always available.

The brief renders inline in the right panel, in a read-only view. A "Start working" button closes the brief and opens the most-recently-updated planned spec in the editor.

## Acceptance criteria

1. `curaye brief` generates output with all six sections (Current State, What Was Planned, Where You Left Off, Decisions to Revisit, Suggested First Step, Vision Check).
2. The "Where You Left Off" section identifies the most-recently updated planned spec by its `updated` frontmatter date.
3. The "Suggested First Step" recommends the spec with `status: building` if one exists, otherwise the highest-impact `status: ready` spec.
4. Running `curaye brief --no-ai` produces a deterministic brief with no AI provider required.
5. `curaye brief --save` writes a dated file to `.curaye/briefs/` and confirms the path.
6. The desktop app shows the re-entry prompt for projects not opened in Curaye for > 30 days.
7. Clicking "Generate re-entry brief" in the desktop app streams the brief into the right panel.
8. "Start working" after the brief opens the recommended spec in the editor.
9. A project with no planned specs generates a brief that says so explicitly — no hallucinated spec list.
10. A project with no AI provider generates a deterministic brief with accurate data — no error, no empty sections.
